## Окружение Python

Нужен Python 3.11+ и Google Chrome для парсинга.
Создайте виртуальное окружение в корне проекта:

```bash
python -m venv .venv
```

Активируйте его. Команда для Windows (PowerShell):

```bash
.venv\Scripts\Activate.ps1
```

Установите зависимости:

```bash
pip install -r requirements.txt
```

```bash
python -m playwright install chromium
```

Драйверы БД нужны только своему бэкенду, поэтому вынесены в extras. Для
конвейера нужен PostgreSQL:

```bash
pip install -e ".[postgres]"
```

ClickHouse — только для старого сценария:

```bash
pip install -e ".[clickhouse]"
```

Chromium от Playwright на Windows иногда не стартует с ошибкой
`side-by-side configuration is incorrect`. Тогда укажите уже установленный в
системе браузер: `BROWSER_CHANNEL=chrome` или `BROWSER_CHANNEL=msedge`. Для
ежедневных прогонов на хосте рекомендован `chrome` — с ним сделаны все замеры.

## Настройки .env

Скопируйте `.env.example` в `.env` и заполните значения. Минимум для
конвейера:

```text
BROWSER_CHANNEL=chrome
POSTGRES_PASSWORD=<пароль базы в docker-compose>
PG_DSN=postgresql://ozon:<тот же пароль>@127.0.0.1:5433/ozon
```

Все параметры — в [configuration.md](configuration.md).

## Доступ к Gmail

Нужен только для входа в аккаунт Ozon (`get_cookies.py`); сбору данных он не
нужен. Код подтверждения входа читается из почты через Gmail API. Нужен
OAuth-клиент типа «Desktop app» из Google Cloud Console. Сохраните его как
`credentials.json` в корне проекта. При первом запуске откроется окно
согласия Google, после него refresh-токен ляжет в `token.json`. Используется
только scope `gmail.readonly`.

Если OAuth-приложение в Google Cloud в статусе **Testing**, refresh-токен
живёт 7 дней: для постоянной работы приложение нужно перевести в
**Production**.

## Сессия Ozon

```bash
python get_cookies.py
```

Перед первым запуском привяжите к аккаунту Ozon (профиль Ozon ID) тот Gmail,
к которому выдан доступ через Gmail API, и укажите его в `.env` как `OZON_EMAIL`.

Как устроен вход (проверено на живом сайте):

1. `data.ozon.ru` сначала отдаёт антибот-проверку: HTTP 403, страница
   `Antibot Challenge Page`. Это JS-проверка браузера, через 5–10 секунд она
   сама перезагружает страницу. Скрипт её дожидается (`CHALLENGE_TIMEOUT`).
2. На лендинге формы нет: вход начинается с кнопки «Перейти к аналитике»,
   которая уводит на `sso.ozon.ru` (Ozon ID).
3. В Ozon ID скрипт выбирает «Войти по почте» и вводит `OZON_EMAIL`.
4. Ozon присылает письмо с кодом. Скрипт находит свежее письмо через Gmail API
   (в том числе в «Спаме») и вводит код.
5. После появления cookies авторизации состояние сессии (cookies +
   localStorage) сохраняется в `cookies.json`.

К Gmail скрипт подключается **до** запроса кода: если доступа к почте нет,
попытка входа на Ozon не тратится.

**Почему по почте, а не по телефону.** При входе по телефону способ
подтверждения выбирает сам Ozon: QR-код в приложении, звонок с вводом
последних цифр номера, SMS или письмо. Письмо в этом списке не
гарантировано, а остальные способы через Gmail не автоматизируются. Вход по
почте — единственный путь, где код гарантированно приходит письмом. Вход по
телефону тоже реализован (`LOGIN_METHOD=phone` или `--method phone`):

- код страны +7 в форме выбран отдельно, поэтому вводится только национальная
  часть номера;
- после ввода скрипт сверяет, что приняла маска поля;
- если Ozon предлагает доставку кода на почту, скрипт её выбирает;
- если Ozon выбрал QR-код или звонок, скрипт сразу останавливается с
  объяснением, а не ждёт письмо, которое не придёт.

При неудачном входе снимок экрана сохраняется в `logs/get_cookies_failure.png`.

Если сессия уже сохранена, повторный запуск ничего не делает. Перезаписать
её можно флагом `--force`. Если автоматический вход невозможен (например,
Ozon просит капчу), войдите вручную: скрипт откроет браузер и подождёт, пока
вы войдёте (`MANUAL_LOGIN_TIMEOUT`).

```bash
python get_cookies.py --manual
```

Ежедневный прогон сессию не проверяет (`schedule.ensure_session: false`).
Если её включить, шаг `ensure_session` будет перевыпускать сессию, когда файл
старше `schedule.session_max_age_days`. Учтите: парсер не сохраняет токены,
которые Ozon обновляет на лету, поэтому сохранённая сессия быстро перестаёт
действовать. 06.10.2026 сессия от 25.09 при загрузке страницы оказалась
гостевой, при этом прогоны собирали 1200 из 1200 SKU.

Без сессии в корне проекта лежит `cookies.json` с пустым состоянием
`{"cookies": [], "origins": []}`. Файл можно и удалить: парсер работает без
него. Но docker-compose подключает его томом, и отсутствующий файл Docker
подменил бы пустым каталогом.

## База и первый запуск

Поднимите PostgreSQL (только база, на `127.0.0.1:5433`):

```bash
docker compose up -d
```

Сформируйте panel, замерьте скорость, зарегистрируйте ежедневный прогон:

```bash
python -m price_panel discover
```

```bash
python -m price_panel benchmark
```

```bash
powershell -ExecutionPolicy Bypass -File scripts\register_windows_task.ps1
```

Схема базы создаётся автоматически при первой команде. Дальше — в
[operations.md](operations.md).
