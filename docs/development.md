## Тесты

```bash
pytest
```

189 проверок в 18 файлах. Тесты не ходят в сеть:

- `test_pipeline.py` использует настоящий браузер, но все ответы Ozon
  подменяются заглушками;
- discovery проверяется на поддельном источнике со структурой ответов живого
  сайта;
- предохранитель — на настоящем цикле парсера с подменённым браузером.

Логи тестов пишутся во временный каталог (`OZON_LOG_DIR`), а не в `logs/`.

Девять проверок `test_warehouse.py` работают с настоящим PostgreSQL и
запускаются, только если задан `TEST_PG_DSN`. Имя базы должно содержать
`test`: фикстура пересоздаёт схему `public`.

```bash
TEST_PG_DSN=postgresql://ozon:change-me@localhost:5433/ozon_test pytest
```

```bash

```

```bash

```

Pyright проверяет типы с теми же настройками, что и Pylance в VS Code
(`[tool.pyright]` в `pyproject.toml`). Правила ruff — там же.

## Миграции

Схема меняется только новой миграцией, уже применённые файлы не правятся:

1. Создайте `ozon_parser/migrations/NNNN_описание.sql` со следующим номером.
2. Пишите SQL, рассчитанный на однократное применение: миграции идут одной
   транзакцией по порядку номеров, учёт — в `schema_migrations`.
3. Проверьте на тестовой базе: `TEST_PG_DSN=... pytest tests/test_warehouse.py`.

Миграция применится сама при следующей команде `python -m ozon_parser`.

## Документация

Документация лежит рядом с кодом и меняется в том же коммите, что и
поведение, которое она описывает. Структура — в [docs/README.md](README.md).
Цифры производительности и результаты живых проверок записываются только по
фактическим запускам — с датой и условиями.
