# Настройки

Конфигурация разделена на два файла:

- **`.env`** — секреты и всё, что зависит от машины: `PG_DSN`, учётные данные
  PostgreSQL для docker-compose, почта Ozon, файлы сессии, режим браузера. Там
  же остаются параметры парсера карточек (`REQUEST_DELAY`, `MAX_RETRIES`,
  `PAGE_TIMEOUT`, `BATCH_SIZE` …). Их читают и `parse_ozon.py`, и конвейер,
  так что источник истины один. Файл не попадает в git; шаблон —
  `.env.example`.
- **`config.yaml`** — поведение конвейера: категории, `panel_size`,
  `top_ratio`, глубина хвоста, `seed`, темп discovery, экспорт CSV, порог
  доли успеха, расписание, параметры benchmark. Секретов здесь нет, файл в
  репозитории. Он проверяется при каждом запуске, ошибки называют конкретное
  поле. Другой файл можно указать через `PIPELINE_CONFIG` или
  `python -m ozon_parser --config <путь>`.

Переменные окружения процесса имеют приоритет над `.env`: например,
`scripts/run_daily.ps1` выставляет `HEADLESS=1` поверх значения из файла.

- [.env](#env)
- [config.yaml](#configyaml)

## .env

### Вход на Ozon и Gmail

| Переменная               | По умолчанию                  | Назначение |
| ------------------------ | ----------------------------- | ---------- |
| `LOGIN_METHOD`           | `email`                       | `email` — код письмом на `OZON_EMAIL`; `phone` — способ подтверждения выбирает Ozon |
| `OZON_EMAIL`             | —                             | Gmail, привязанный к аккаунту Ozon (тот же, что в Gmail API) |
| `OZON_PHONE`             | —                             | Телефон для `LOGIN_METHOD=phone`, в любом формате |
| `GMAIL_CREDENTIALS_FILE` | `credentials.json`            | OAuth-клиент «Desktop app» из Google Cloud Console |
| `GMAIL_TOKEN_FILE`       | `token.json`                  | Refresh-токен, создаётся при первом входе |
| `GMAIL_SENDER_FILTER`    | `from:(ozon.ru OR ozon.com)`  | Фильтр отправителя письма с кодом |
| `GMAIL_WAIT_TIMEOUT`     | `180`                         | Сколько секунд ждать письмо |
| `GMAIL_POLL_INTERVAL`    | `5`                           | Интервал опроса почты, с |
| `MANUAL_LOGIN_TIMEOUT`   | `300`                         | Сколько ждать входа человека в `get_cookies.py --manual`, с |
| `ELEMENT_TIMEOUT`        | `20000`                       | Таймаут появления поля формы входа, мс |
| `TYPING_DELAY_MS`        | `80`                          | Задержка между символами при вводе, мс |

### Браузер и парсер карточек

| Переменная                 | По умолчанию | Назначение |
| -------------------------- | ------------ | ---------- |
| `HEADLESS`                 | `0`          | `1` — браузер без окна |
| `BROWSER_CHANNEL`          | пусто        | Пусто — Chromium от Playwright; `chrome` / `msedge` — браузер, установленный в системе. На хосте рабочий вариант — `chrome` |
| `USER_AGENT`               | Chrome на Windows | User-Agent контекста браузера |
| `PAGE_TIMEOUT`             | `60000`      | Таймаут загрузки страницы, мс |
| `LOAD_STATE_TIMEOUT`       | `15000`      | Сколько ждать полной загрузки сверх `domcontentloaded`, мс |
| `PAGE_SETTLE_MS`           | `1500`       | Пауза после загрузки перед запросом к API, мс |
| `CHALLENGE_TIMEOUT`        | `30`         | Сколько ждать прохождения антибот-проверки, с. Не прошла — SKU не повторяется, ошибка `antibot`, снимок экрана в `logs/` |
| `REQUEST_DELAY`            | `3.0`        | Пауза между SKU, с. Не занижайте |
| `MAX_RETRIES`              | `2`          | Повторы SKU (и страницы discovery) при обычных ошибках |
| `MAX_BROWSER_RESTARTS`     | `2`          | Сколько раз перезапускать упавший браузер за прогон |
| `MAX_CONSECUTIVE_FAILURES` | `10`         | Предохранитель: столько SKU подряд без данных — прогон останавливается; `0` — выключен |
| `MAX_CONSECUTIVE_CHALLENGES` | `3`        | Меньший порог предохранителя: столько SKU подряд с непройденной антибот-проверкой; `0` — не учитывать отдельно |
| `BATCH_SIZE`               | `50`         | Старый сценарий: сбрасывать собранное в хранилище каждые N товаров |

## config.yaml

### discovery

| Ключ                  | Сейчас                 | Назначение |
| --------------------- | ---------------------- | ---------- |
| `seed`                | `ozon-panel-2026-09`   | Зерно генератора; к нему добавляется имя категории |
| `top_ratio`           | `0.4`                  | Доля top в panel; остальное — `tail_random`. Можно задать и `tail_ratio`, сумма должна быть 1 |
| `request_delay`       | `5.0`                  | Пауза между запросами к листингу от конца предыдущего, с (не меньше 0.5) |
| `request_jitter`      | `0.3`                  | Случайный разброс паузы: 0.3 → от 0.7 до 1.3 паузы |
| `block_backoff`       | `[10, 60, 180, 300]`   | Ожидания при отказе Ozon (403/429/заглушка), с; после каждого — новая сессия браузера |
| `category_pause`      | `60`                   | Пауза между категориями, с |
| `tail_max_page`       | `600`                  | Глубже какой страницы хвост не берётся (выдача обрывается на 646–684-й) |
| `tail_items_per_page` | `3`                    | Сколько товаров хвоста брать с одной страницы |
| `export_csv`          | `data/panel_skus.csv`  | Куда выгрузить активную panel после discover; пусто — не выгружать |
| `categories`          | 4 категории            | См. ниже |

Категория:

| Ключ                  | Обязателен           | Назначение |
| --------------------- | -------------------- | ---------- |
| `name`                | да                   | Латиница в нижнем регистре, цифры, `_`; попадает в `sku_panel.category` |
| `title`               | нет                  | Человекочитаемое название для вывода |
| `source`              | нет                  | `ozon_listing` (по умолчанию) или `data_ozon` |
| `url`                 | для `ozon_listing`   | `https://www.ozon.ru/category/<slug>-<id>/`; Ozon определяет категорию по id |
| `category_ids`        | для `data_ozon`      | id узлов дерева data.ozon.ru (уровень 3 — `descriptionTypeId`) |
| `sort_attribute`      | нет                  | Метрика сортировки для `data_ozon`, по умолчанию `sum_gmv` |
| `panel_size`          | да                   | Сколько SKU держать в panel категории |
| `top_ratio`, `tail_max_page`, `tail_items_per_page` | нет | Переопределяют общие значения |

Сейчас: `phone_cases`, `smartphones`, `coffee_machines`,
`string_accessories`, по 300 SKU. Почему эти категории и такой размер — в
[discovery.md](discovery.md#sampling) и [performance.md](performance.md#размер-panel).

### schedule

| Ключ                   | Сейчас          | Назначение |
| ---------------------- | --------------- | ---------- |
| `daily_at`             | `"08:45"`       | Время ежедневного прогона, `ЧЧ:ММ` |
| `timezone`             | `Europe/Moscow` | Часовой пояс `daily_at` и вывода `runs` |
| `run_on_start`         | `false`         | Контейнерный планировщик: прогнать сразу при старте |
| `ensure_session`       | `true`          | Перед парсингом проверить сессию и при необходимости войти заново |
| `session_max_age_days` | `14`            | Старше скольких дней сессия перевыпускается |
| `parse_timeout_hours`  | `10`            | Жёсткий предел длительности ежедневного прогона вместе с повтором |
| `block_retries`        | `1`             | Сколько раз повторить прогон, остановленный блокировкой Ozon (`blocked`); `0` — не повторять, максимум 3 |
| `block_retry_delay_hours` | `3`          | Через сколько часов повтор (от 0,5 до 12). Повтор берёт только SKU, которых за сегодня ещё нет, и не начинается, если до конца `parse_timeout_hours` меньше часа |

После изменения `daily_at` или `parse_timeout_hours` перезапустите
`scripts/register_windows_task.ps1` (см.
[operations.md](operations.md#планировщик-заданий-windows)). Как работает
повтор — [operations.md](operations.md#повтор-после-блокировки).

### benchmark

| Ключ            | Сейчас | Назначение |

| `sample_size`   | `50`   | Сколько случайных SKU panel парсить при замере |
